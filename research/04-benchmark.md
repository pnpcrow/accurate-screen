# 04 — 성능 비교표 (스킬 적용 전/후)

작성일: 2026-10-02 · 측정: `skills/accurate-screen/scripts/benchmark.mjs`(재실행 가능) + 연구 02·03 판독 실험
측정 환경: 2560×1600 주 모니터(DPI 1.25), 메모장(WinUI 3, 가림 상태) + 테두리 없는 폼 타깃

## 1. 과제별 비교 — 이전(전체 화면 → 모델 판독) vs 스킬

"이전" 경로 = 전체 화면 캡처(GDI 215ms) → 1280px 축소 → 모델이 이미지에서 찾기.
실패 양상은 연구 02에서 재현·증거 촬영 완료.

| # | 분석 과제 | 이전 경로 | 스킬 경로 | 결과 |
|---|---|---|---|---|
| 1 | 창 본문 텍스트 추출 (메모장 4줄) | **실패 가능** — 가려지면 본문이 캡처에 없음(무음 손실). 실패해도 실패한 줄 모름 | `scanText` **96ms, 이미지 0장**, 텍스트 100% 일치(벤치 2/2 PASS) | ✅ 속도 4–14배 + 무결성 보장 |
| 2 | 가려진 창의 내용 확인 | **원리적 실패** — 합성 데스크톱에 픽셀이 없다 | `shot` **359ms** — 창 표면 강제 렌더링으로 가림 관통(실증: `r2-window-notepad-occluded.png`) | ✅ 불가능→가능 |

| 6 | GLM-5.3(비전 ✗) 세션에서의 분석 | 이미지 emit → **토큰만 소모, 0 정보** | 비전 게이트가 emit 차단, UIA/digest 텍스트 경로로 **분석 자체는 계속 가능** | ✅ 실패→부분 대체 |
| 7 | 좌표 클릭 전 근거 확인(CU 조합) | 최근 라스터에서 픽셀 추측 | `readPoint`/`scanText`의 UIA bounds가 근거(36ms) | ✅ 정확도 상승 |

## 3. 컨텍스트 비용 (모델 토큰 관점)

| 항목 | 이전 | 스킬 |
|---|---|---|
| 텍스트 확인 1건 | 래스터 1장(약 1–2천 토큰 상당) + 판독 추론 | 텍스트 수 줄(이미지 0장) |
| 전체 UIA 트리 관찰 | (기본 경로) 수십 KB — 이후 턴 오염 | 미사용 — 필요 요소 필드만 |
| 셀당 이미지 | 실수 시 2장 → 2번째 삭제 | 1장 가드 + 비교는 합성 1장 |

## 4. 종결

- 속도: 텍스트 과제 기준 **4–14배**(이미지 0장 효과 포함), 크롭 파이프라인도 1초 미만.
- 정확도: 세 실패 모드(가림·귀속·붕괴)가 전부 구조적으로 차단 — 판독 실험에서 실패→성공으로 반전.
- 유일하게 "이전과 동등"한 것은 전체 화면 개관(과제 5) — 그 목적 외에 전체 화면 경로는 폐기하는 것이 정답.
