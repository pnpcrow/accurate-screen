# 07 — 출력 버퍼 직접 캡처: "이름만으로 가려진 창까지" (Claude/Codex 방식)

작성일: 2026-10-02 · 배경: 사용자 지적 — "윈도우가 출력 버퍼를 이미 만들어둔 상태인데 화면을
캡처해서 분석하다 보니 다른 윈도우에 가려지면 찾지 못한다. 출력 버퍼가 있는 경우 얼마든지
윈도우 이름만으로 출력 이미지를 캡처할 수 있어야 한다(Claude/Codex가 그 방법 — 동영상·게임
중에도 출력 이미지를 완벽 분석). 이 부분 개선이 필요하다."

## 1. 판정 요약

지적은 두 갈래였고 둘 다 맞다:

1. **찾기(find)**: 전체 화면 캡처에서는 가려진 창을 *찾을 수 없다* → 구조적 해법으로
   `findWindows(제목·앱이름 검색)`을 추가했다(전체 창 테이블 스캔, 가려진/최소화 창도 발견, 수 ms).
2. **캡처(capture)**: 창의 **출력 버퍼**에서 직접 담는 경로(`captureWindowPngVerifiedAsync`,
   PrintWindow 계열)는 화면 z-order와 무관하다 — 이번에 이름 겨냥과 함께 일급 경로로
   승격하고 실증했다. 스킬은 이미 이 경로를 Tier 1으로 쓰고 있었지만, "이름만으로" 겨냥하는
   편의와 가림 상태의 판별 지표가 없었다 — 보강했다.

## 2. 실증 결과 (증거: `captures/r7-*`)

### 시험 A — 제목만으로 가려진 창 캡처

리그: 제목 달린 투명 창 3개(COW-TARGET/OX-BG/RAM-BG) + 불투명 가림막(BLOCKER, 어두운 적색)이
COW-TARGET 위를 덮는 배치.

| 단계 | 결과 |
|---|---|
| `findWindows("COW-TARGET")` | 화면에 안 보이는데도 pid 35120·windowId·bounds를 즉시 반환 ✓ |
| `shot("COW-TARGET")` — **제목 문자열만** | 완전한 dog 이미지(match 0.95, margin 0.37), `hasAlpha:true`(창 자체 버퍼 경로) ✓ |
| 같은 순간 화면 합성 | 대부분 가림막에 덮임(좌표 대조) — 픽셀-only 경로라면 타깃 불가였을 것 |

### 시험 B — 최소화된 창 (경계 확인)

| 상태 | 결과 |
|---|---|
| 최소화(iconic) 후 캡처 | **거부 — `invalid_target`** (출력 버퍼가 해제된다) |
| 최소화 상태 UIA | 살아 있다(Image 요소 발견) — 텍스트 경로는 계속 가능 |
| 복구 | 동기 `ShowWindow(9)`는 타 프로세스에서 무시될 수 있음 → **`ShowWindowAsync(9)`로 복구 성공** |
| 복구 후 캡처 | 다시 성공(bird, match margin 0.36, hasAlpha) — 버퍼 재생성 확인 |

결론: "버퍼가 살아 있으면(가림·백그라운드) 이름만으로 캡처, 버퍼가 해제된 경우(최소화)만
UIA 또는 복구 후 캡처"가 정확한 경계다. 동영상·게임 시나리오(작업 중 다른 창 뒤에서 재생)는
전부 전자에 해당한다.

### 시험 C — 연속 렌더링 창(동영상·게임 대리)을 완전히 가리고 라이브 캡처

리그: 16ms DispatcherTimer로 공·프레임 카운터를 계속 다시 그리는 GPU 합성 창(ANIM)을
불투명 BLOCKER로 **완전히** 덮은 상태.

| 검증 | 결과 |
|---|---|
| 화면 합성(애니 창 중앙 샘플) | (96,30,40) — 가림막 색 그대로 → **화면에서 완전히 안 보임 확인** |
| 버퍼 캡처 1·2 (700ms 간격) | 픽셀 차이 **6.48%** → 실시간 프레임(LIVE) |
| 버퍼 캡처 내용 | `FRAME 1383` + 이동한 공 — 선명, 가림막 픽셀 0 혼입, `hasAlpha:true` |

즉 "작업 중에 뒤에서 동영상/게임이 돌아도 출력 이미지를 완벽히 분석한다"가 이 환경에서도
성립한다 — 단, **exclusive fullscreen·하드웨어 보호 콘텐츠(DRM)는 이번 시험 범위 밖**이다.

## 3. 스킬 반영 (screen-read.mjs + SKILL.md)

- `findWindows(query, {includeHidden})` 신설 — 제목·앱이름으로 전체 창 검색, 가려진/최소화 포함 가능.
- `resolve`가 **창 제목 매칭**을 지원(앱 이름 → 창 제목 순, 캐시 히트 시 pid 생존 검증 추가 —
  죽은 pid 캐시가 새 검색을 막는 버그 수정).
- `shot` digest에 `image.hasAlpha` 추가 — 버퍼 경로(알파 보존) vs 화면 합성 판별 지표(연구 06 관측 계승).
- SKILL.md: Tier 1에 "이름만으로 겨냥(가림 무관)" 레시피 + 최소화 예외(ShowWindowAsync) 명시,
  하드 룰 4를 "창 내용은 출력 버퍼에서 직접"으로 강화.

## 4. 시험 중 잡은 결함·함정 (재현자용)

1. **WPF 무활성 창은 렌더 루프가 멈춘다**: `CompositionTarget.Rendering`은 무효화가 없으면
   틱하지 않아 애니메이션 창이 프레임 0에 고정되었다(첫 시도 실패 원인). DispatcherTimer(16ms)
   강제 무효화로 해결 — "GPU 연속 렌더링" 대리 물성을 만들 때 주의.
2. **GDI PNG는 4채널**: 픽셀 샘플링 시 `raw()` 채널 수(info.channels)를 존중하지 않으면
   스트라이드가 어긋나 엉뚱한 회색 평균이 나온다(이번 시험에서 실제로 오판했다가 수정).
3. **타 프로세스 창 복구는 `ShowWindowAsync`**: 동기 ShowWindow(9)는 반환값 true와 무관하게
   무시될 수 있다.
4. 죽은 pid를 가리키는 이름 캐시 — resolve가 생존 검증 없이 신뢰하면 "no window" 오류(실제 발생).

## 5. 미해결·후속

- exclusive fullscreen 게임/DRM 보호 콘텐츠 캡처는 미검증(환경에 없음) — 필요 시 별도 시험.
- cloaked UWP(설정 앱 등)는 여전히 blank 감지 → UIA 경로(기존 설계 유지).
- 창 이름이 전혀 없는(제목 빈 문자열) 창은 제목 검색 불가 — pid/핸들 경로 또는 UIA(연구 06 리그) 사용.
