# 03 — 우회 기법 실증 (무엇이 실패를 되돌리는가)

조사일: 2026-10-02 · 전부 이 세션에서 실측. 증거: `captures/`, 수치는 본문 인라인.

기법들은 배타적이지 않다 — **계층(layer)으로 쓴다**: 텍스트는 UIA로 먼저 시도하고, 픽셀이
필요하면 창 캡처, 좁게 보려면 UIA 좌표로 크롭, 귀속은 항상 메타데이터로.

## M1 — 창 단위 검증 캡처: 가림(F1) 관통

`captureWindowPngVerifiedAsync(windowId, pid, bundleId)` — PrintWindow 계열로 **창 자신의
표면**을 강제 렌더링해 캡처한다. 화면 합성과 무관하므로 뒤에 가려진 창도 온전하다.

실측: 폼에 가려진 메모장을 GDI 전체화면으로 찍으면 본문이 소실(02 발견 A) — 같은 순간 같은 창을
이 경로로 캡처하니 본문 4줄이 전부 렌더링(`r2-window-notepad-occluded.png`, **216ms**).

조건: `ok:false`(cloaked/최소화)이면 재시도하지 말고 UIA 경로로. 빈 캡처 감지는 필수 —
PNG bytes/kpx ≈ 17(빈 화면) vs 62–175(내용) 임계(이전 프로젝트 실측 재사용).

## M2 — UIA 텍스트 경로: 이미지 0장으로 텍스트·값·귀속을 동시에

`elementAtPoint(gx, gy)`는 그 점의 최상위 요소를 {role, title, value, bounds, ownerPid}로
돌려준다(≈36ms). **가려진 창도 UIA 트리에는 살아 있다** — z-order만 주의하면 된다.

실측:
- 테두리 없는 폼의 라벨 3개: 텍스트 + 소유 pid + 정확한 rect를 이미지 없이 획득 → 귀속(F3)·
  좌표(F2의 해결 재료)를 동시에 해결.
- 메모장 본문: Document 요소의 `value`에 **파일 전체 텍스트**가 그대로 있었다(줄바꿈 보존).
  이미지 판독과 비교해 오판률 0, 비용 ~40ms.
- 격자 스캔(스킬의 `scanText`): 4×4 히트테스트로 창 내 텍스트 요소 일괄 수집 — 메모장에서
  **16지점 100ms**, 중복 제거 후 1개 Document + 전문.

노이즈 통제: value는 잘라서(예: 200자) 쓴다. 트리 전체를 텍스트로 받는 것(51KB 플러딩)과
정반대로, **필요한 요소의 필요한 필드만** 모델 컨텍스트에 들어간다.

한계: z-order(가장 앞의 요소가 히트) — 특정 창의 요소를 찍으려면 그 창의 가려지지 않은 점을
고르거나 창을 앞으로. UIA가 죽은 앱(일부 게임/DirectX)은 이 경로 자체가 없다 → M1으로.

## M3 — UIA 유도 크롭: "핸들 → 좌표 → 캡처 → 잘라보기"

사용자가 제안한 파이프라인 그대로. UIA가 준 rect를 캡처 좌표계로 변환해 잘라내고 확대한다.

실측(폼의 소형 텍스트 2줄, 201ms 전 과정):
1. `listApplications` 2ms → 폼 pid 확정
2. `listWindows` 1ms → bounds [520,300,760,440]
3. `elementAtPoint` ×2 → 라벨 rect [552,410,342,28]·[552,438,535,25] + **텍스트 확보**
4. 창 캡처 216ms (760×440)
5. rect−원점 변환 후 extract + 2배 확대 13ms → `r3-pipeline-crop.png`

전체 화면 1280px에서 판독 실패했던 9pt 한국어 줄이 **크롭에서는 완판**. 분석 대상 면적이
2560×1600 → 551×69로 **1/107**이 되었고, 텍스트 높이는 2배로 증가(02의 8px 법칙을 작은
화면에서도 충족). 크롭 후 확대 배율은 `min(2×, 900px 폭)` 정도가 적정 — 과도한 확대는 토큰만 늘린다.

## M4 — 메타데이터 주입: 귀속(F3)의 구조적 해결

두 겹으로 뜬다:

1. **digest(텍스트)**: 캡처 반환값에 항상 `{app, pid, windowId, 화면 bounds, method, ms,
   blank, bytesPerKpx}`를 붙인다. 모델은 이미지와 digest를 한 쌍으로만 기억한다.
2. **리본(이미지 안)**: 이미지 상단에 `[앱이름] pid · 창 핸들 · 화면좌표` 리본을 **확장
   (extend)** 방식으로 새로 만든 영역에 그린다. 75ms 실측(`r3-annotated-notepad.png`).

교훈(실수에서): 리본을 기존 픽셀 위에 **덮으면(overlay)** 창 상단 UI를 파괴한다. 반드시 캔버스를
늘려 새 영역에 그린다. 모델 입장에서 귀속 질문은 "픽셀을 보고 추론"이 아니라 "리본을 읽고 인용"으로
바뀐다 — 근거 인용이므로 환각이 원리적으로 사라진다.

## M5 — 의도 선행 프로토콜: Tool Call 전에 추출 대상을 정리

캡처 전에 반드시 한 줄 의도를 쓰게 한다(스킬 §0):
`{목표: 무엇을 알려고 하는가, 타깃 앱 추정, 기대 필드/값, 확인 방법(UIA|픽셀)}`
→ 효과: (a) 타깃 핸들을 먼저 찾으므로 캡처 범위가 창/요소로 좁아지고 (b) emit 예산(셀 1장)을
정확히 소비할 수 있고 (c) "일단 찍어 보기"로 생기는 노이즈 턴이 사라진다. 사용자 가설대로
**모델의 주의가 미리 정해진 상태로 이미지를 받게 되는 것이 핵심**이다.

## M6 — 인코딩·예산 규칙 (02 실측의 규칙화)

- 창 캡처는 **폭 ≤1280이면 리사이즈하지 않는다**(네이티브가 최고 판독력, 800px 이상이면 판독 무리 없음).
- 축소 시에도 폭 하한 800px. 640px는 한계선 — 금지 수준.
- 기본 JPEG Q80(82ms), 크롭·확대·텍스트 검증용은 PNG(palette).
- 셀당 래스터 1장(2번째는 삭제된다). 비교가 필요하면 합성 이미지(레이블 달아 1장으로)로 퉁친다.
- 크롭 확대는 ≤2배, 폭 ≤900px — 그 이상은 정보가 아니라 토큰.

## M7 — 비전 게이트 (F6)

세션 모델이 GLM-5.3(비전 ✗)이면 이미지 emit 자체가 낭비다. 능력표 판정 → `vision("none")` 기록 →
emit 하드 차단, UIA/캡처 digest 등 도구 텍스트 경로만 사용. 판정 절차는 이전 프로젝트
(06-vision-gate.md)의 것을 그대로 계승: 현재 모델 → 같은 플랜 → Individual Plan → 도구 전용.

## 적용 순서 (의사결정 트리)

```
무엇을 알려고 하는가? (의도 선언)
├─ 텍스트/값/상태 → M2 UIA (이미지 없음, ~40ms)
│   └─ UIA 죽음/값 없음 → M1 창 캡처 + (필요시) M3 크롭
├─ 배치/모양/색/그래픽 → M1 창 캡처 (+digest, 필요시 M4 리본)
│   └─ 소형 타깃 → M3 UIA rect 크롭
├─ "화면 전체에 뭐가 떠 있나" → GDI 전체화면 1장 (가림 한계 고지 필수)
└─ 비전 없는 세션 → UIA/캡처 digest 텍스트 경로만 (M7)
```
