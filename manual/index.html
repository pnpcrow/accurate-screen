accurate-screen

가려진 창까지 이름만으로 읽어 내는 화면 분석 스킬 · 누구나 따라 이해하는 사용 설명서
🪟 Windows 전용 🤖 ZCode · GLM 세션용 🖱️ Computer Use 없이도 동작

1이것이 무엇인가요?

accurate-screen은 화면 위 앱의 내용을 빠르고 정확하게 읽어 내는 스킬입니다.

비유하면, 온 책상을 한 장 찍어 눈으로 뒤지는 대신 책상 위 사물마다 붙어 있는 자기 앨범에서 그림을 직접 꺼내 보는 방법으로 바꾸는 도구예요.

창(윈도우)은 열리는 순간 자기만의 그림 앨범, 즉 출력 버퍼를 만듭니다. 이 앨범은 화면 앞쪽을 누가 가리든 그대로 살아 있어요. accurate-screen은 그 앨범에서 이름만으로 그림을 꺼내 옵니다.

2왜 필요한가요? — 사진 방식의 세 가지 실패

전체 화면을 찍어서 AI에게 보여 주는 방식은 실제 시험에서 세 가지로 실패했습니다(research/02).

🙈 가림 손실
앞의 창에 가려진 내용은 사진 자체에 없고, 사진엔 그 흔적도 남지 않아요. AI는 "내용이 없다"고 오판합니다.
🎭 귀속 불능
테두리·제목이 없는 창의 그림은 누구 것인지 픽셀만으로 알 수 없어요. 비전 모델도 원리적으로 불가능합니다.
🔍 글자 붕괴
큰 화면을 줄여서 보여 주면 작은 글자가 8픽셀 아래로 부서져 읽을 수 없게 됩니다.

accurate-screen은 이 세 문제를 "사진을 잘 찍는" 것으로가 아니라 방법 자체를 바꿔서 피합니다.

3시작하기 전에 — 준비물 체크리스트

준비물확인설명
Windows 10/11필수측정된 모든 경로가 Windows용입니다.
ZCode (node_repl 사용 가능)필수스킬의 도우미(screen-read.mjs)를 실행하는 통입니다.
Computer Use 플러그인자동이미지 처리용 sharp를 여기서 빌려 씁니다. 설치돼 있으면 끝.
비전 모델 세션 (예: GLM-5.3-Flash)이미지를 보일 때만비전이 없는 세션(GLM-5.3)이면 도구 전용 모드로 텍스트만 읽습니다 — 그래도 분석은 계속 됩니다.

Computer Use(마우스·키보드 조작 기능)를 켜지 않아도 이 스킬의 '읽기'는 전부 동작합니다.

4작동 방식 — 네 단계

  1. 의도를 먼저 적는다. "메모장에 적힌 코드 값을 알고 싶다"처럼 한 줄로 씁니다.
    무엇을 볼지 미리 정해면, 쓸데없는 큰 사진을 찍는 일이 사라집니다.
  2. 이름으로 창을 겨냥한다. findWindows("메모장") — 화면에 안 보이는 창도 목록에서 바로 찾아 냅니다(제목·앱 이름 검색).
    가려져 있어도 pid(창의 주민번호)와 좌표가 나옵니다. 이 시점에서 찾기는 끝.
  3. 알맞은 방법으로 읽는다. 글자·값이 목적이면 UIA로 텍스트를 직접 읽습니다(이미지 0장, 약 40ms). 모양·그림이 목적이면 창의 출력 버퍼에서 직접 캡처합니다(약 0.25초). 가려진 창도, 동영상·게임처럼 계속 그림이 바뀌는 창도 온전히 담깁니다.
    사진 방식과 달리 가림에 강하고, 소속 앱 정보가 결과에 함께 붙습니다.
  4. 필요한 부분만 크게 확인한다. UIA가 알려 준 좌표로 그 부분만 잘라 2배 확대해 봅니다. 캡처에는 빨간 리본(앱 이름·pid·좌표)이 붙어 어느 창의 그림인지 절대 헷갈리지 않습니다.
    분석 면적이 1/100로 줄어 작은 글자도 선명하게 읽힙니다.

6문제가 생겼을 때 — 증상 → 해결

증상해결
결과에 blank: true가 나옴 (하얀/빈 그림)그 창은 지금 그림을 그릴 수 없는 뒷배경 상태입니다. 재시도하지 말고 UIA 텍스트 경로(scanText)로 전환하세요.
invalid_target 오류가 나옴창이 최소화되어 있으면 출력 버퍼가 잠시 해제됩니다. ShowWindowAsync(창핸들, 9)으로 복구한 뒤 다시 캡처하거나, UIA 텍스트로 읽으세요.
ambiguous(이름이 겹친다) 오류같은 이름의 창이 여러 개입니다. 검색어를 더 길게 쓰거나 pid로 직접 지정하세요. 쌍둥이 창은 절대 겉모습으로 고르지 않습니다.
이미지를 봐도 내용을 모르겠음세션 모델이 비전이 아닐 수 있습니다(GLM-5.3 등). 같은 플랜의 비전 모델로 바꾸거나 도구 전용 모드(텍스트만)로 진행하세요.
전체 화면 사진에서 내용이 빈 채로 나옴가림입니다. 전체 화면은 '무엇이 떠 있는지 훑기'용이고, 내용 읽기는 반드시 창 단위 캡처를 쓰세요.

7용어 사전

어려운 말쉬운 말
출력 버퍼창이 자기 그림을 보관하는 개인 앨범. 화면에 가려져도 앨범은 그대로입니다.
UIA (접근성 트리)앱이 스스로 내놓는 글자·단추의 목록표. 사진 없이 내용을 읽게 해 줍니다.
cloaked (클로킹)겉보기엔 있지만 화면에 그림을 그리지 않는 상태. 사진엔 빈 것으로 나옵니다.
digest캡처에 함께 붙는 출처 스티커(앱 이름·pid·좌표). 귀속의 근거가 됩니다.
래스터 예산AI에게 보여 줄 수 있는 그림은 한 번에 한 장이라는 규칙입니다.
TL;DR (English). accurate-screen is a Windows skill for ZCode/GLM sessions that optimizes the app-capture path: it reads text via the accessibility tree in ~40 ms with zero images, and captures window content directly from the window's own output buffer by name alone — so occluded windows and continuously-rendering content (video, games) come through complete and live, in ~0.25 s. Every capture carries provenance metadata (app, pid, window handle, screen bounds), which eliminated misattribution in a stress test with identical twin windows. It works with or without Computer Use. This page is the beginner manual; see the repository for the skill itself and the measured research notes.
